 tp final: desarrollo guiado por la spec

 respuestas

 1. ¿cuál es el orden de trabajo del desarrollo guiado por la spec?

spec → plan → tareas → implementar

 2. ¿qué hacer si la spec no aclara una situación?

el arquitecto deja la duda anotada como pregunta. el cliente decide, el analista actualiza la spec y después el arquitecto actualiza el plan.

 3. ¿cómo probar una regla de cancelación con menos de 24 horas de anticipación?

usar un reloj propio que se pueda fijar y adelantar durante los tests.

 4. ¿qué código responde un usuario autenticado sin permiso de administrador?

403: sé quién sos, pero no podés pasar.

 5. ¿qué archivos corresponde subir al repositorio?

`.env.example`, `docs/spec.md`, `AGENTS.md`, `.cursor/rules/`, `package-lock.json` y las migraciones de la base de datos.
